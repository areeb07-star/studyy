You are building "StudyGraph", a production-quality web app for the Multimodal AI Hackathon 2026 (IIT Mandi), Track D: Personalized Tutoring & Adaptive Learning. It will be judged nationally, so quality, polish, correctness, and honest evaluation matter more than feature count.

## GOAL
An AI study companion that ingests lecture videos, textbooks (PDF), and slide decks (PPTX) with NO manual preprocessing, organizes them into a source-linked knowledge graph of topics/concepts/prerequisites, tutors students using cited answers that open the exact page/slide/video timestamp, runs verified adaptive assessments, maintains a per-concept learner model, and evaluates itself with a standard framework.

## HOW TO WORK
- Build in the phases below. After each phase, STOP, summarize what works and what doesn't, and wait for me to say "proceed".
- Prefer working end-to-end over breadth. Every feature must actually function, not be mocked. If something can't be done in this environment, tell me and propose a fallback.
- Keep code clean and modular (clear folders, typed models, docstrings, error handling, logging). Write a README as you go.
- All model names and API keys come from environment variables/Replit Secrets. Make the main LLM, validator LLM (must be a DIFFERENT model from the main one), vision model, and embedding model configurable. Cache LLM outputs in the database to save cost.
- Use hosted APIs for heavy work (speech-to-text, vision, embeddings) since there is no GPU. Design transcription behind an interface so it can use a hosted STT API or a local faster-whisper model.
- Pre-ingested demo data must persist so the demo never depends on slow live processing.

## TECH STACK
- Frontend: Next.js (React) + Tailwind + shadcn/ui; React Flow (knowledge map); Recharts (charts); a PDF viewer that opens at a given page; a video player that seeks to a timestamp; slide viewer showing rendered slide images.
- Backend: FastAPI (Python) with background workers/queue for ingestion.
- Database: PostgreSQL with pgvector.
- Retrieval: hybrid BM25 + vector search, then a reranker.
- Documents: PyMuPDF for PDFs; python-pptx for slides; render slides to images (LibreOffice if available, otherwise a fallback); yt-dlp for YouTube links; speech-to-text with word/segment timestamps (English and Hindi).
- Embeddings: a multilingual embedding model so Hindi queries retrieve English sources.
- Evaluation: RAGAS (and/or DeepEval).
- Spaced repetition: FSRS or SM-2.

## DATA MODEL (PostgreSQL)
users, courses, sources (type: video/pdf/pptx, title, file path/url, language), units (id, source_id, text, figure_caption, locator JSON {type, page | slide | start_sec/end_sec}, language, embedding), topics, concepts, concept_edges (prerequisite relations), unit_concepts (tags), questions (type, text, options, answer key, difficulty, topic/concept tags, source unit IDs, misconception map per distractor, verified flag, embedding), quizzes, attempts (answer, correctness, partial score, error type), misconceptions, mastery (user, concept, p_known, next_review, stability, evidence log with source = quiz|chat|diagnostic), chat_messages (with citations), flashcards, study_plans, eval_runs.

## PHASE 1: Foundation + Ingestion (Requirement 1a-1d)
Build upload (drag-and-drop for PDF/PPTX/video files plus YouTube links) with per-file live progress. Pipeline, fully automatic:
1. Detect file type and run the matching extractor.
2. PDF: text per page with page numbers, plus page images.
3. Slides: text and speaker notes per slide number, plus rendered slide images.
4. Video: timestamped transcript segments (start/end seconds), Hindi supported; extract keyframes at slide changes.
5. Figures/diagrams (in PDFs, slides, video keyframes): use a vision model to caption and extract content (labels, axes, relationships). Store as searchable units linked to their exact page/slide/timestamp.
6. Chunk everything into units; every unit MUST carry a locator and source ID.
7. Use an LLM to build the hierarchy: topics -> subtopics -> concepts, plus prerequisite edges, merging duplicates across sources.
8. Tag every unit to its concepts, embed it, and index it.
Include a library page listing sources and ingestion status.

## PHASE 2: Grounded Tutor (Requirement 2a-2b)
Chat UI with:
- Hybrid retrieval + reranking.
- A relevance gate: similarity threshold plus an LLM check "can this be answered from the retrieved context?". If not, clearly say it is not covered in the material, and only give outside knowledge in a visually separate, clearly labeled block when appropriate.
- Answers generated with structured output where every claim cites unit IDs.
- A citation verifier pass that checks each cited unit actually supports its claim and fixes or removes unsupported ones.
- Numbered citations that, when clicked, open a side viewer at the EXACT PDF page, slide image, or video timestamp (video player seeks to start_sec).
- Source-grounded explanations of concepts with excerpts.
- Language toggle (English/Hindi/Hinglish): answers in the chosen language while still citing the original-language sources.
- The tutor occasionally asks a short check question to gather mastery evidence.
- Optional voice input and voice output (browser speech APIs or hosted STT/TTS).

## PHASE 3: Assessment Engine (Requirement 3a-3c)
Quiz Builder: student chooses scope (topics, specific sources, or whole course incl. mock-exam mode), question types (MCQ, short answer, numerical), difficulty, and count.
Generation:
- Every question is tagged with topic/concept, source location(s), and difficulty, and is generated from retrieved source units.
- MCQ distractors each map to a NAMED misconception.
Verification (must be implemented, not mocked):
- A second, different LLM independently solves each question; mismatches are dropped and the rejection rate is logged.
- Numerical questions are additionally verified by executing code.
Novelty:
- Embed each question and reject any that are too similar to previously asked questions for that student; track repetition rate.
Grading and feedback:
- MCQ: exact match. Short answer: rubric-based LLM grader using source key points, with partial credit. Numerical: tolerance and units, verified by code.
- Every answer gets cited feedback linking to the source location.
Post-assessment report:
- Score, per-topic breakdown, weak topics, likely misconceptions (from selected distractors and LLM error classification of free-text answers) with cited sources, and recommended next steps.

## PHASE 4: Learner Model + Dashboard (Requirement 4a-4b)
- Bayesian Knowledge Tracing per concept (p_known, p_guess, p_slip, p_learn), updated after every answer.
- FSRS/SM-2 forgetting-curve layer to compute each concept's next review time.
- Prerequisite propagation: low mastery of a prerequisite raises its priority and reduces confidence in dependent concepts.
- Conversation updates: detect signals in chat (repeated confusion, tutor check-question answers, questions about prerequisites) and apply a smaller-weight update, with evidence source = "chat".
- Question selection targets low/uncertain mastery and due reviews, with difficulty matched to mastery.
- Cold start: onboarding with a diagnostic quiz OR an intake conversation that sets priors.
- Dashboard: mastery heatmap, mastery-over-time lines, weak topics, due reviews, streaks, and an explanation of why each concept has its current estimate.

## PHASE 5: System Evaluation (Requirement 5a-5c)
Create /eval with scripts and an in-app Evaluation page showing results:
- Team-built test set (50-100 questions) with known source locations: text-only, figure-based, cross-source, Hindi, and 20-30% off-material queries.
- RAGAS (or DeepEval) metrics: faithfulness, answer relevancy, context precision, context recall.
- Extra metrics: retrieval hit rate at top-k against labeled source locations, citation accuracy, refusal accuracy on off-material queries.
